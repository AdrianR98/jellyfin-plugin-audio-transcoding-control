## What caused the abort, and what remains unknown

The old guard required the bound VideosController deviceId to equal the authenticated device claim exactly. It returned progressive-device-claim-mismatch before looking up the validated PlaybackInfo context. This conflated two native fields with different purposes. The supplied productive log establishes a nonempty unequal bound value; it does not reveal the values, their origins or whether the context would have matched. It cannot establish a particular encoding difference, device alias or authentication fallback on the user's Fire TV.

In the pinned server, AuthorizationContext obtains DeviceId from the decoded native authorization header or, when absent, from the record belonging to the authenticated token. CustomAuthenticationHandler turns that result into the device claim. A plain DeviceId query is not used to authenticate a device. MediaInfoHelper takes its device from that claim; StreamBuilder assigns it to StreamInfo. StreamInfo.ToUrl appends DeviceId verbatim, whereas ASP.NET decodes the query before binding VideosController's argument. For example, literal plus and percent sequences can produce a transport value different from the original opaque claim. VideosController documents its query device as the client job-routing identity used when stopping encoding. StreamingHelpers also uses it in the native output cache key. The plugin does not change that value or the native cache behavior.

Android TV 0.20.0 uses SDK 1.8.12. PlaybackManager passes the returned TranscodingUrl to ApiClient.createUrl with ignorePathParameters=true. UrlBuilder preserves its encoded query. API requests add the SDK authorization header; the Media3 HTTP factory uses a separate OkHttp data source, without that API request wrapper. Native token-record fallback can therefore be relevant for media requests. The client also derives per-user device IDs, so different authenticated identities must not be guessed equivalent. These are source findings, not captured Fire TV traffic.

## Correction and security boundary

Only after a successful native PlaybackInfo response does its existing bounded, transient proof additionally retain the single decoded DeviceId field of the matching source's native TranscodingUrl. No URL or token is retained. Absolute/unsupported URLs and invalid or ambiguous device fields do not provide an alternative match.

The progressive filter still looks up the context by the full exact authenticated user, authenticated device and native play session. Current rule fingerprint, item, source, audio track, native permissions, encoder and audio ceilings remain mandatory. A query cannot select another authenticated context. The optional routing device must agree with its single actual query value and must exactly equal either the authenticated device or the transport value issued in this same proof. No trimming, case folding, second URL decoding, device alias derivation or authentication-claim replacement occurs. An absent routing field remains optional as before; authenticated identity/context remain mandatory.

This safely covers a demonstrated native transport difference. It deliberately does not bridge different authenticated device claims between requests. If the real client sends a third unissued value, or authenticates as a different device, the request still bypasses. The next sanitized report must identify that condition before another compatibility change is justified. Successful hardware AC3 5.1 is not claimed for this release.

## Diagnostics

- 2403 records retention, native-offer device state/reference, comparison to the authenticated device and negotiationRef.
- 3205 records native claim counts, decoded query count, bound-field presence, their origins and process-pseudonymized references. Header presence is boolean only; a header's presence does not prove the device came from it. Exact header-versus-token-record origin is not inferred or reconstructed from credentials.
- 3206 records lookup outcome and separate authenticated user/device, item, rule, bound-to-claim, bound-to-native-offer and query-to-bound comparisons. Unavailable comparisons explicitly say not-evaluated.
- 3207 records exact-authenticated-device, exact-native-issued-transport-device or optional-routing-device-absent. 3201 has distinct missing/ambiguous authentication, context-not-found, item mismatch, changed rule, ambiguous/invalid query, query/argument disagreement and neither-authenticated-nor-issued reasons.

negotiationRef is an HMAC of the canonical native play-session UUID with the existing process-random salt; the same reference connects 2403 with progressive events in one server process. References are diagnostic only, never cache/authentication keys. No raw identities, token/header contents, URLs or media paths are logged. Context-not-found can mean expiry/eviction/restart, an unknown session, or a different authenticated user/device; no cross-device context search is performed.
