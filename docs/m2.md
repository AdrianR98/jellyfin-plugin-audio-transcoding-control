# M2 implementation and verification

Historical 0.2.0 record. The [0.2.1 dashboard hotfix](m2.1.md) supersedes its UI verification status; schema 2 and playback policies remain unchanged.

Version 0.2.0.0 targets Jellyfin 10.11.11. This document supersedes earlier milestone descriptions of configuration and packaging; historical M1 evidence remains valid only for its stated scope.

## Configuration and matching

`PluginConfiguration` schema 2 stores the master switch, ordered `Rules`, `Diagnostics` and `UiLanguage`. Each rule has a stable UUID, name, switch, device/user arrays with independent explicit All flags, target `ac3`, ceilings, preservation switches and detailed diagnostics. Maximum 64 rules and 256 entries per selection list. The UI generates new UUIDs and disables duplicates.

Device IDs compare exactly, case sensitively. User IDs compare as GUIDs. A single valid authenticated device/user identity is mandatory even for All rules. Missing/duplicate claims, empty user GUIDs, malformed selection values, unsupported policy limits and duplicate rule IDs cannot select a rule. Empty selections do not imply All. Within axes OR; across axes AND; the first enabled valid match wins. A safety bypass after selection never falls through to a lower rule.

Migration clones the previous configuration, preserves the master/legacy activation switches and exact singleton selections, and writes only this plugin's own configuration. A legacy enabled or partially filled rule receives one stable internal rule UUID. Explicit All flags remain false. Legacy debug logging maps to the Debug development preset. New installs remain disabled with no rules. Repeated normalization does not append another migrated rule. Future schema versions disable processing and are not written back as a downgrade. Invalid legacy selections remain nonmatching and require administrator correction before saving an enabled rule.

Jellyfin serializes the plugin's own configuration as XML below its configured plugins/configurations directory; native authenticated `/Plugins/{pluginId}/Configuration` handles loading/saving. Obsolete legacy fields are omitted from schema 2 XML. The dashboard loads users/devices through the existing API client and retains only selection/display fields from responses; it never stores device access tokens. Unavailable saved selections stay explicit.

## Native policy boundaries

The original native POST MediaInfoController action filter and host checks are retained. The plugin prepares a deep profile copy, narrows eligible streaming audio to AC3 and adds required channel/bitrate conditions. Original profiles, video constraints and subtitle properties are not mutated. Native user permissions and encoder availability are checked; no permission is enabled. Lower native limits remain authoritative. Mono/stereo preservation bypasses transformation entirely. Disabling it permits encoding without requesting an upmix.

Disabling compatible AC3 preservation removes video DirectPlay candidates from the request copy and explicitly sets the native `allowAudioStreamCopy` action argument to false. This only narrows an audio-copy permission and lets the native controller decide. The plugin does not loosen video settings or force video encoding. All preparation precedes these request-local writes. `next()` executes once; native controller failures retain their native behavior.

Supported scope remains deliberately conservative: local accessible video; explicit unique media source; known selected 1/2/6/8-channel AC3/AAC/EAC3/TrueHD/DTS/DCA track; existing AC3-capable HLS TS/MP4 streaming paths. Unknown/derived graphs, live/remote sources, missing data, denied rights and tighter client channel ceilings bypass unchanged. An intended offer is not a guaranteed client stream.

## Native diagnostics

Categories: `Jellyfin.Plugin.AudioTranscodingControl.Plugin` and `.Filters.PlaybackInfoActionFilter`. Configuration uses a configuration correlation label; every PlaybackInfo request has a fresh correlation ID attached to all its events. Device/user pseudonyms use a process-local random HMAC salt; restarting intentionally changes references. Rule IDs are internal configuration UUIDs, not identity references. Rule names are sanitized before logging.

| Event IDs | Content |
| --- | --- |
| 1000, 1002, 1003, 1090 | Initialization/load, save, migration, validation codes |
| 2000 | Relevant request, safe client/version, pseudonymous identities |
| 2100–2102 | Ordered matching outcomes, selected rule or bypass |
| 2200–2201 | Effective permissions and policy safety skips |
| 2300–2301 | Selected source audio and available video/HDR/DV metadata |
| 2400–2402 | Profile counts, preserved video constraints, controlled snapshots and intended AC3 limits |
| 2500–2504 | Read-only native response offers, source metadata and discrepancies |
| 2900–2902 | Safe exception type/method stack and fallback decisions |
| 2990–2992 | Plugin-only total, matching and transformation timings |

The threshold supports Error/Warning/Information/Debug/Trace. Native Debug/Trace are used if enabled. Otherwise, when the native logger accepts Information, the helper uses native Information with structured `DiagnosticLevel=Debug/Trace` and a visible original-level label. This is necessary because the existing global provider minimum can discard lower-level events before a plugin can deliver them. No provider, file sink or global config override is installed. A global Warning/Error threshold can still suppress these diagnostics. Configure levels in the dashboard; no restart is required.

Detailed matching and trace profile snapshots require Trace. The Debug development preset enables all category switches, but Trace is needed for these most detailed entries. Rule-level diagnostics gate source/profile/response details; global matching and performance can explain why no rule was selected.

No logging-only network/database requests are made. Existing metadata lookups are reused. Expensive profile serialization is gated on both category and level. No per-frame, packet or segment logs. Exceptions exclude messages, inner exception payloads, file paths and argument values; method stacks remain available. Profile details include only allowlisted codec/protocol values and scalar limits/counts. Full authenticated URLs and native request/response objects are never logged. URL analysis reads allowlisted offer parameters without changing the response. Metadata and offered query parameters are explicitly distinguished from actual encoded output and client use.
