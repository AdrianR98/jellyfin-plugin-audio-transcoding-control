# M2.4 — verified playback association and settings dashboard

Jellyfin 10.11.11; plugin 0.2.4.0. GUID and schema 2 are unchanged. No production installation, configuration change or restart.

## Native identity root cause

Jellyfin's [AuthorizationContext](https://github.com/jellyfin/jellyfin/blob/1fbd8739292cce610231be93daf43368733edf63/Jellyfin.Server.Implementations/Security/AuthorizationContext.cs) prefers the decoded authorization-header device. Without it, the authenticated token's native registration supplies the device. The token record's device ID is not updated to the header ID. Android TV 0.20.1 [credential login](https://github.com/jellyfin/jellyfin-androidtv/blob/ddd51d00b290b8d3ba16662e42a55120a3ad0aab/app/src/main/java/org/jellyfin/androidtv/auth/repository/AuthenticationRepository.kt) derives its ID from the user name, whereas the [active API session](https://github.com/jellyfin/jellyfin-androidtv/blob/ddd51d00b290b8d3ba16662e42a55120a3ad0aab/app/src/main/java/org/jellyfin/androidtv/auth/repository/SessionRepository.kt) derives it from the user UUID. These can differ for the same credential. The headerless media request then has a different native device claim from PlaybackInfo. The previous device-keyed context cache could never find it; URL decoding was not the cause of this production pattern.

Each request now verifies the unique native user-token record through IDeviceManager. A full 256-bit HMAC with a process-random secret binds that credential to user and native PlaySessionId. Only this non-reversible binding is cached; raw credentials are neither retained nor logged. The current device must equal the negotiated native device or that same credential's verified registration device. Query/routing IDs must still match the negotiated device or its exact issued transport value. Names, versions, IP addresses and session IDs alone never establish authorization.

Contexts remain bounded to 256 entries/12 hours. Conflicting device/item/source contexts under the same binding become unusable. Different credentials, users, unrelated device claims and sessions do not inherit a context. Native authentication/revocation, current media access, source, selected track, matching policy and permissions are revalidated. The negotiated device selects the current ordered rule after credential verification; fingerprints record changes instead of permanently freezing an obsolete policy. Native device IDs are client assertions, not hardware attestation: possession/sharing of the same bearer credential cannot prove a physical Fire TV's identity.

## Tracks, preservation and event 2503

Track index is mutable state. Every relevant progressive request resolves its requested track from the bound real source, then applies the current AC3/stereo/preservation limits. Compatible AC3 and preserved stereo retain their original negotiation profile while keeping a validated context for later tracks. This also avoids unnecessarily narrowing direct-play capabilities of a file containing other audio codecs.

Android TV's [PlaybackController](https://github.com/jellyfin/jellyfin-androidtv/blob/ddd51d00b290b8d3ba16662e42a55120a3ad0aab/app/src/main/java/org/jellyfin/androidtv/ui/playback/PlaybackController.java) either changes an available local ExoPlayer track or automatically renegotiates at the current position. [PlaybackManager](https://github.com/jellyfin/jellyfin-androidtv/blob/ddd51d00b290b8d3ba16662e42a55120a3ad0aab/app/src/main/java/org/jellyfin/androidtv/ui/playback/PlaybackManager.kt) requests new PlaybackInfo for the server-streaming path. No manual movie restart is required by the plugin. A wholly local client-side switch without a server request cannot be intercepted by a server plugin.

Event 2503 describes the native audio-only-permission fallback: StreamBuilder does not choose the transformed video profile when video/remux permissions are denied. Editing an offered URL would not validate subsequent regenerated requests or mutable tracks, so the existing progressive hook remains necessary; no additional interception or response rewriting was added. Video arguments/processing and native encoder jobs/cache are unchanged. Existing cached output is not rewritten; automatic new negotiations produce new native sessions. Compatible AC3 can direct play when native capabilities permit it; progressive copying still requires native remux/copy permission. Otherwise AC3 is re-encoded without granting permissions.

New Debug events 2404/2405 and 3208/3209 distinguish native identity, verified credential association and current rule; 3210 reports current versus initial audio index. Existing 2403/3205/3206/3207 and negotiationRef remain. References are process-pseudonymized; no raw credentials, IDs, URLs or paths are logged.

## Dashboard and registration lifecycle

The native versioned page has Audio rules/Diagnostics views, compact summaries/cards, accessible switches, keyboard-compatible overflow actions, collapsible editors, scoped responsive CSS and embedded SVG icons. English is default; German remains optional. Bitrate displays kbit/s while retaining bit/s internally. All/Selected controls retain inactive selections and explain their effective scope. Field validation, save-failure retention, diagnostics forwarding and the stable page alias remain.

Native /Devices records are deduplicated by exact ID and grouped by normalized display name/client for presentation only. Newest entries appear first; older entries collapse. Every ID remains independently selectable. Activity windows are 30/60/90/180/365 days or All time, default 90, remembered only in this browser's plugin preference. Selected/missing registrations remain visible, unknown activity is separate, and search can reveal older entries. Native active/controllable sessions distinguish connected registrations from timestamp-only recent use. Metadata is a snapshot, not a network-presence guarantee.

Replacement suggestions require matching display metadata and newer recent activity; replacing or keeping both requires explicit administrator confirmation and then Save. Nothing transfers automatically. Dismissal is local to the open page. The plugin never deletes devices, revokes tokens or terminates sessions. Cleanup links to native device management.

## Focused verification and remaining limits

- Release build: zero warnings. 50 test cases retain the existing coverage and add credential/track isolation and compatible multi-track AC3 preservation checks. The requested AC3 → TrueHD 7.1 → DTS-HD MA 6.1 → DTS-ES 6.1 → AC3 sequence is covered with source-metadata fixtures, including policy/permission changes and unrelated-call rejection.
- [Native FFmpeg evidence](evidence/m24-native-streaming.json): different header/token-record devices with the same credential, headerless generated-URL fetches, original AC3 direct playback, TrueHD/DTS/AC3 transitions, seeking/resume and an unrelated same-user credential control. Actual arguments include `-codec:v:0 copy -codec:a:0 ac3 -ac 6 -ab 640000`. Native test input is six-channel TrueHD/DTS core, not actual 7.1 TrueHD or DTS-HD MA/DTS-ES bitstreams.
- Native UI smoke: initialization/reopen, scopes, selected/missing ID preservation, activity/search/group ordering, confirmed reassignment, move/duplicate/delete/add, validation, save/reload, simulated network failure with retained edits, English/German, diagnostics/report copying, reduced motion and dark/light/narrow layouts. No new framework, dependencies or CI. Test processes were stopped.

User-reported production baseline: original English AC3 reaches the receiver as Dolby Digital 5.1; switching tracks produced AAC 5.1 while retaining HEVC copy. Real Fire TV/receiver output after this release, HDR/Dolby Vision and Atmos behavior remain user-verifiable, not established by these synthetic checks.
