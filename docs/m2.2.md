# M2.2 — progressive MKV and selection diagnostics

Version 0.2.2.0 targets Jellyfin 10.11.11. Existing GUID, schema 2 and rules are preserved. No production server changes.

## Cause and resolution

Native MediaSourceManager sets video-source SupportsTranscoding from EnableVideoPlaybackTranscoding, and SupportsDirectStream from EnablePlaybackRemuxing. With playback/audio permissions true and video/remux false, both flags are false. The old plugin incorrectly required SupportsTranscoding=true, rejecting an allowed local audio-transcoding case as unsupported-or-ambiguous-source. Missing source ID was a separate unnecessarily strict rejection.

Native StreamBuilder cannot choose a video transcoding profile when both flags are false. MediaInfoHelper can nevertheless offer a progressive HTTP fallback because audio transcoding is permitted. This explains why a HLS profile change alone does not prevent the native AAC/MKV fallback. The isolated native controller reproduces it, including an unextended /stream URL.

Pinned sources: [MediaSourceManager](https://github.com/jellyfin/jellyfin/blob/1fbd8739292cce610231be93daf43368733edf63/Emby.Server.Implementations/Library/MediaSourceManager.cs), [StreamBuilder](https://github.com/jellyfin/jellyfin/blob/1fbd8739292cce610231be93daf43368733edf63/MediaBrowser.Model/Dlna/StreamBuilder.cs), [MediaInfoHelper](https://github.com/jellyfin/jellyfin/blob/1fbd8739292cce610231be93daf43368733edf63/Jellyfin.Api/Helpers/MediaInfoHelper.cs). Android TV 0.20.0 PlaybackManager obtains PlaybackInfo and uses the returned TranscodingUrl for non-direct playback; track changes negotiate again. This is source behavior, not captured traffic from the user's Fire TV.

Source selection follows native query-before-body semantics. Explicit IDs must match uniquely; an omitted/empty ID resolves only when the entire native source list contains exactly one entry. Remote/infinite/open-required/non-file sources still bypass. Audio selection uses query/body, native default, then the only audio track if unique. Ambiguous/external/unknown tracks bypass. Known 1–8 channel source metadata includes DTS 6.1. Audio permission and encoder checks are independent of the video-source flag; the native flags and permissions are never modified.

Deep profile copies retain video/subtitle restrictions and support existing AC3-capable HLS TS/MP4 or HTTP MKV profiles. AAC-only or unsupported capability paths still bypass with specific reasons instead of inventing client capabilities.

## Scoped streaming hook

Successful preparation and a successful native PlaybackInfo response retain a bounded transient context by authenticated device/user and native play session, including item/source/track and rule fingerprint. At most 256 contexts are retained for at most 12 hours, without persistence; successful retention is logged. Eviction/restart/expiry requires fresh PlaybackInfo. Current authentication, rule and permissions are checked again on every relevant streaming request.

The additional filter handles only native VideosController progressive GET/HEAD: explicit MKV/Matroska, or unextended streaming from a MKV source. Static files, packed parameters, live/remote/download contexts, mismatched sessions/sources/tracks, changed rules and unrelated callers retain native behavior. It is limited to native video transcoding being forbidden, the reported fallback case, and requires audio-transcoding permission and allowed video copy. Native EncodingHelper then forces video copy. No video arguments, permissions, original files or responses are changed.

Only supported AAC/AC3 or omitted audio codec requests in that validated context are narrowed to AC3. Existing requested bitrate/channel ceilings are preserved or tightened, using valid AC3 bitrates up to the rule maximum. Compatible AC3 copy requires both the rule and existing remux/copy permission. With remux denied, AC3 is re-encoded rather than granting remux permission. This is not a universal AAC replacement.

Already-running native encoder jobs/output files are not rewritten or stopped. Start fresh playback after rule changes, and obtain new PlaybackInfo after server restart/context eviction. An unmatched-device control must use its own authenticated device and native device/session identity, rather than reuse another device's cached output session.

## Diagnostics and checkbox UI

Debug 2210–2212 distinguish source/track selection, ID/index presence and origin, counts/uniqueness, native flags, safe codec/channels and container/protocol. Distinct reason codes replace the old aggregate abort. Debug 2200/2202 and 2398/2399 show effective/requested restrictions and controlled profile summaries. Events 2403 and 3200–3204 distinguish retained negotiation, progressive checks, skips and audio changes; 3290/3291/3299 cover safe exceptions and plugin-only timing. Offers/request parameters are never described as executed FFmpeg output.

Searchable checkbox rows show selected counts/highlighting, wrapping names, available client/version/activity and distinct local references. Filtering never removes selected values. Saved unavailable entries remain selected; All remains explicit. Reload retains the edited rule when its internal ID still exists.

Validation highlights the affected rule/field and displays localized inline guidance. Diagnostic events include one-based RulePosition, internal RuleId, Field and specific reason codes. Missing selections use device-selection-required and user-selection-required. SelectedDevices/SelectedUsers contain counts, never raw identities. Saved/active totals and restored selections are logged. Native authenticated API requests retain actual HTTP statuses (200/204 observed); events without an HTTP response explicitly use unknown. The administrator-only bridge validates nullable status and bounded allowlisted rule/field/reason/count metadata.

## Verification and limits

Release build and 46 test cases: the previous 42 retained plus four focused source/native-controller/MKV cases. No new test infrastructure, dependencies or CI. Sanitized evidence: [native MKV](evidence/m22-native-streaming.json), [new UI behavior](evidence/m22-ui.json).

The disposable Windows Jellyfin 10.11.11 instance used synthetic 4K HEVC SDR/TrueHD. Actual FFmpeg and ffprobe demonstrate video copy and AC3 six-channel/640000 bit/s, including the native generated progressive URL. Unnegotiated and unmatched-device controls retain AAC; compatible AC3 copy was demonstrated with remux permission. The synthetic TrueHD encoder produced six input channels; eight-channel TrueHD and seven-channel DTS use focused fixtures, not native bitstreams in this check. No Fire TV hardware, receiver, Atmos output, HDR or Dolby Vision preservation proof is claimed.

The targeted native browser check verified checkbox/filter selection persistence, separate device/user validation reasons, field highlighting, internal rule references, saved/enabled counts, real HTTP status and restored selections. Native UI logs were checked for controlled metadata and absence of raw fixture identities. The disposable process was stopped.
