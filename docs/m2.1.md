# 0.2.1 dashboard hotfix

## Root cause and fix

The shipped Jellyfin Web 10.11.11 `node_modules.jellyfin-apiclient.bundle.js` exposes `getPluginConfiguration`, `getUsers`, `getUrl` and `ajax`, but **no `getDevices` method**. The 0.2.0 Promise.all array called getPluginConfiguration first, then threw synchronously at getDevices; getUsers was never reached. This exactly explains the configuration-only network trace. The catch hid the TypeError, and the disabled Add/Save state followed the failed load. Reload was registered but retried the same broken call.

0.2.1 calls the existing authenticated transport for GET /Devices. Native responses are the PascalCase plugin configuration, Devices query result with an Items array, and Users array. Only display/selection fields are retained. Diagnostics.Level is a string in this plugin; the UI also recognizes native numeric Trace..Error values defensively. Null selection arrays remain empty, never All; invalid configuration is displayed as an error instead of overwritten.

The existing embedded inline script and pageshow contract match the official plugin template. Initialization now starts explicitly and guards overlapping pageshow calls. Bound elements are scoped to the current page, handlers are installed before API loading, and a prior controller on the same root is disposed before rebinding. Page hide invalidates stale loads; reopening reloads saved data while retaining unsaved edits when appropriate. Field/handler failures and missing DOM elements get controlled diagnostic codes. No global error hook claims errors from unrelated content scripts. The reported external content.js Illegal invocation is not established as an ATC error.

## Native menu

The same registered page name, audiotranscodingcontrol, is used from plugin details and the sidebar. PluginPageInfo enables EnableInMainMenu with DisplayName Audio Transcoding Control, MenuSection server and MenuIcon graphic_eq. All properties exist in the pinned server. The actual 10.11.11 React dashboard queries enabled pages and renders them under Plugins using DisplayName; it uses its own generic plugin icon and does not consume MenuSection/MenuIcon there. No web file modification or other plugin is required.

[Official server contract](https://github.com/jellyfin/jellyfin/blob/v10.11.11/MediaBrowser.Model/Plugins/PluginPageInfo.cs), [official template lifecycle](https://github.com/jellyfin/jellyfin-plugin-template/blob/c93225a0a5a76d3843db05b4b5b77fcfc482fba3/Jellyfin.Plugin.Template/Configuration/configPage.html). The local native bundles from the already verified 10.11.11 archive supplied the ApiClient and dashboard behavior evidence.

## Diagnostics and errors

[ATC:UI] emits version, random page-session correlation, monotonically increasing event sequence, lifecycle/handler actions, API stages/durations, available HTTP statuses, processing/render counts, control actions and validation/save outcomes. It does not log names, rule values, device/user IDs, response payloads, authenticated URLs, headers or raw exception messages/stacks. Safe stacks retain a small known function vocabulary with numeric positions; unknown/external frames have no source path.

The page has separate English/German configuration/device/user/save/interface errors, loading/save states and a copyable bounded report (last 100 events). On load failure, data-dependent controls are visibly disabled; Reload, language and report remain available. Failed saves preserve edits and allow retry. The legacy API returns parsed values without success status, so status 0 means unavailable. Failed fetches expose HTTP status where available; network-blocked requests have no HTTP response.

POST /AudioTranscodingControl/UiDiagnostics uses native RequiresElevation authorization. Batches are bounded (16 KB / at most 32 events, client sends at most 16). All event/step/reason/type/DOM labels and safe stack frames are validated before native ILogger output. Unknown client text is rejected, not echoed. Native events 3100/3101 use Information/Warning independently of plugin configuration, allowing bootstrap diagnosis. Global filters still apply. Forwarding failure stops forwarding for that page session and never prevents local diagnosis or configuration editing. No token or separate sink/config file is introduced.

## Targeted verification

- Release build, existing 41 tests and one small endpoint security/validation test; no new dependencies/frameworks/workflows.
- Disposable Windows Jellyfin 10.11.11 with its own data/config/cache/log paths and loopback-only binding, using the actual bundled Web 10.11.11. No media/library/FFmpeg integration rerun.
- Actual browser: configuration/devices/users load; master switch, Add, edit, duplicate, enable/disable, move up/down, delete with confirmation, multi-device/multi-user selection, logging level/options/Debug preset, English/German, Save and Reload work. Saved settings and selections survive native reload and reopening.
- Native sidebar entry observed under Plugins and opened the same configuration page. Reopening produces one handler registration for the new page; a single duplicate action produces one rule copy. Diagnostic report copying and controlled action records verified.
- Blocking GET /Devices gives the specific device error, Save disabled and Reload enabled; unblocking and Reload recover the UI. Blocking configuration access during Save preserves edits; retry after unblocking succeeds. Temporary browser network blocks were removed.
- Native diagnostics endpoint: administrator succeeds, anonymous 401, nonadministrator 403, unrecognized diagnostic text 400. Native UI event forwarding observed in the isolated server log.

No production installation, settings change or restart performed. Production update, user-specific extensions/other plugins, mobile browser variants and hardware playback remain user-owned practical checks. Existing schema 2 and transcoding rules/logic are unchanged. Earlier release assets and catalog versions are retained.
